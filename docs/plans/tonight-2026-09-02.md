## Track A — OWNER, do these two things and nothing else

### A1. AWS account (~20 min) — DO THIS FIRST

1. aws.amazon.com → create account (email, phone, card for identity verification).
2. **Billing → Budgets → $10/month with an email alert.** Before anything runs.
3. MFA on the root user, then stop using root.
4. IAM Identity Center → create an admin user with `AdministratorAccess`.
5. Terminal: `aws login` → pick that user. Temporary auto-refreshing credentials; no keys to leak.
6. **Use `us-east-1`. Never change it.**

**You do NOT need the Anthropic use-case form.** That form is Anthropic-specific. Amazon's own
models (Titan, Nova) are not sold through AWS Marketplace, have no product keys, and are
available immediately. Titan is what we're using.

Say the word when `aws sts get-caller-identity` returns and the AWS work starts within minutes.

### A2. Label the gold set (~20–60 min) — can be done while A1's account verifies

```bash
cp data/gold-pairs-unlabeled.jsonl data/gold-pairs.jsonl
# fill in "label" on each row: duplicate | related | unrelated
node scripts/ml/evaluate.mjs
```

Each row already has both titles, both GitHub URLs, and all four method scores. Rows are
shuffled so you can't drift a threshold as you go.

**You do not have to do all 150.** Label 40–60 and you get a real result with wider confidence
intervals — which is the honest outcome at small n anyway, and reporting the interval rather
than the point estimate is the correct move. **Without any labels there is no measured result
at all, and the evaluation bullet stays hypothetical.**

Highest-value rows are at the top strata (`lex_top`, `dense_top`) — those are the hard cases
where the methods disagree, and they carry the most information per label.

### B1. Amazon Titan embedding backend
Implement the stubbed `bedrock` path in `lib/dedup/embed.ts` using
`amazon.titan-embed-text-v2:0`, write indexes to separate files so both encoders coexist, and

Ships label-free too: Spearman rank correlation and top-k overlap between the two encoders is a
real, reportable comparison that needs neither labels nor an approval.

### B2. Minimal LangGraph triage agent
Four nodes — `load_backlog → assess → propose → [interrupt] → apply_decisions` — with a genuine
human-in-the-loop `interrupt()`, a checkpointer, and **dry-run by default**. Uses the existing
`aiStructuredCall` and `lib/github.ts`; adds no LLM client.

The `interrupt()` is the whole point. If only one thing works, it must be that.

## Track C — stretch, only if A1 lands early

**Deploy the container to ECS Express Mode.** Everything is pre-built. Four known traps:
`--platform linux/amd64` (Apple Silicon → x86_64, and Express auto-rolls-back on failure so the
evidence hides); `--health-check-path /api/health`; pin `maxTaskCount: 1`; and `deploy.yml`
calls the wrong command for Express services.

## Two data-quality findings worth mentioning in an interview

These are worth more than any model, because catching them is the skill being tested:

- **Author leak:** all 24 human-authored PRs merged (100%) while all 26 rejections were bot PRs
  — so a merge-prediction model trained on all 70 would learn "is this a human?" and report a
  fake ~0.95 AUC.
- **Temporal confound:** the queue stalled 2026-07-28, so "not merged" largely means "filed
  after triage stopped," not "bad idea."
